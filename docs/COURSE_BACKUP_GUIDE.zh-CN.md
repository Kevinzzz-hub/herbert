# Herbert 课程备份与恢复学习指南

## 1. 这个模块解决什么问题

Herbert 免费版把课程保存在浏览器的 IndexedDB 中。这样不需要云端存储费用，但清除网站数据、换浏览器或换电脑时，本地记录不会自动跟随用户。

课程备份让用户主动下载一份自己的学习数据，并在需要时导入恢复。它是免费版的“手动同步”，也是未来 VIP 自动云同步的基础。

## 2. 备份里有什么

包含：

- 课程名称与说明；
- PDF 文件名、页数和提取后的分页文字；
- AI 总结和页码引用；
- 知识卡片、测验题和最近成绩；
- 创建、更新和学习时间。

不包含：

- DeepSeek API Key；
- 登录邮箱、密码、验证码或账号 ID；
- Supabase 密钥；
- 原始 PDF 文件。

备份包含 PDF 提取文字，因此它仍然属于用户的私人学习资料，应妥善保管。

## 3. 为什么使用带版本号的 JSON

备份文件使用 `.herbert-course.json` 后缀，本质是可读的 JSON。文件最外层包含：

```text
format: "herbert-course-backup"
version: 1
exportedAt: 导出时间
course: 课程信息
documents: PDF 记录数组
```

`format` 防止用户误选普通 JSON，`version` 让未来的数据结构升级可以被明确识别。JSON 也比私有二进制格式更透明，出现问题时更容易排查。

## 4. 导入为什么不能直接写数据库

导入文件属于外部输入，即使它曾由 Herbert 导出，也可能被编辑、损坏或替换。`lib/course-backup.ts` 会先检查：

- 文件不超过 25 MB；
- 格式标识和版本正确；
- 课程名称、说明和时间有效；
- PDF 数量、页数和文字总量在限制内；
- 总结、页码引用、卡片和题目结构完整；
- 引用页码确实存在；
- 测验成绩没有出现负数或超过总题数。

只有完整通过校验的数据才能交给本地数据库。

## 5. 为什么导入不会覆盖旧课程

备份不保存内部课程 ID、文档 ID 和账号 ID。导入时 Herbert 会：

1. 为课程生成新的 ID；
2. 为每份 PDF 生成新的 ID；
3. 把记录归属到当前登录用户；
4. 在同一个 IndexedDB 事务中写入课程和全部文档。

因此同一份备份可以导入多次，每次都会成为独立课程。事务保证导入要么全部完成，要么完全不写入，不会留下只有一半资料的课程。

## 6. 关键文件

- `web/lib/course-backup.ts`：定义格式、剥离账号信息、序列化和验证外部文件。
- `web/lib/local-library.ts`：读取整门课程，并用事务导入新的课程和文档记录。
- `web/app/CourseLibrary.tsx`：提供“备份”和“导入课程备份”按钮，以及成功或失败提示。

## 7. 你可以怎样验收

1. 在书架中找到一门包含 PDF 的课程。
2. 点击课程卡片上的“备份”。
3. 确认浏览器下载一个 `.herbert-course.json` 文件。
4. 点击书架顶部的“导入课程备份”，选择刚下载的文件。
5. 确认书架出现一门同名的新课程，PDF 数量一致。
6. 打开新课程，确认总结、卡片和最近测验成绩能够恢复。
7. 尝试选择一个普通 JSON 文件，确认 Herbert 拒绝导入并给出明确提示。

## 8. 你应该掌握的知识

- 导出格式也是产品接口，需要版本号；
- 外部文件永远不能直接信任；
- 校验负责保证数据形状，数据库事务负责保证写入完整性；
- 重新生成 ID 可以避免覆盖和归属错误；
- 本地优先不等于无法迁移，手动备份可以在零云成本下提供数据可携带性。
