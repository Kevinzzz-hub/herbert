# Herbert 本地课程资料模块

## 这次解决什么问题

上一版本只在页面内保存当前 PDF 的状态。刷新、离开课程或关机后，文件名、提取文字和总结都会消失。

这个版本把课程资料存入浏览器自带的 IndexedDB。它是浏览器提供的本地数据库，适合保存比 `localStorage` 更大、结构更复杂的数据。

## 产品决策

Herbert 继续采用本地优先模式，但现在用登录账号隔离同一浏览器里的不同用户：

- 用户需要登录，课程数据仍不上传云端；
- 开发者不承担课程数据库与 PDF 存储费用；
- 原始 PDF 文件不保存；
- 提取后的分页文字和 AI 总结只保存在当前浏览器，并记录所属用户 ID；
- 同一浏览器关机、重启和刷新后仍能读取；
- 换设备、换浏览器、换网站地址或清除站点数据后不能自动恢复。

未来的 VIP 版本可以在不重写页面的前提下增加课程云同步、自动备份和更大容量。免费版仍可保留本地课程模式。

## 数据关系

```text
Course（课程）
  ├── ownerId（所属登录用户）
  └── Document（文档记录）
        ├── 文件名、大小、页数
        ├── 提取后的分页文字
        ├── AI 总结与页码引用
        └── pending / complete / failed 状态
```

代码把数据库操作集中在 `web/lib/local-library.ts`。页面只调用“列出课程”“保存文档”“完成总结”等函数，不直接操作 IndexedDB。将来增加云端版时，可以用相同的操作接口替换底层实现。

## 一次总结的数据流

1. 浏览器读取用户选择的 PDF，并提取每一页文字。
2. 在请求 DeepSeek 前，Herbert 先生成文档编号并写入 `pending` 本地记录。
3. 服务器调用 DeepSeek，返回结构化总结。
4. 浏览器把总结写回同一条记录，并将状态改为 `complete`。
5. 如果请求失败，记录改为 `failed`；用户可以直接使用已经保存的提取文字重试，不需要重新选择 PDF。

这套顺序很重要：AI 结果有成本且不可完全复现，先建立记录可以避免页面意外关闭后什么都没有留下。

## 隐私边界

保存在本机：课程、文件名、提取文字、总结、状态。

不会保存：原始 PDF 文件。

会临时发送到服务器：生成总结、回答问题或制作复习材料所需的提取文字。服务器当前不把这些内容写入课程数据库。

## 当前限制

- 记录不能跨浏览器或跨设备同步；
- 浏览器的隐私模式可能禁用或临时保存 IndexedDB；
- 清除 Herbert 的网站数据会删除全部课程；
- 本地开发地址和正式网站地址属于两个不同存储空间；
- 当前还没有导出与导入整个课程的功能。

## 验收步骤

1. 创建一门新课程。
2. 进入课程，选择一份可复制文字的 PDF，并完成总结。
3. 返回课程资料，确认出现文件名、页数和“已保存”状态。
4. 刷新页面，重新进入课程并打开这份总结。
5. 完全关闭浏览器或电脑，再次打开同一地址，确认记录仍存在。
6. 对已保存的总结继续提问，确认页码引用仍可使用。
7. 删除文档记录，确认它从课程中消失；删除课程，确认其全部文档一起删除。

## 你应该掌握的知识

- React state 只负责当前页面显示，不等于持久化；
- IndexedDB 是浏览器中的异步数据库；
- 主键把一条 AI 生成结果稳定地标识出来；
- `courseId` 建立课程和文档的一对多关系；
- 状态字段让失败和中断也能被恢复；
- 数据访问层把产品页面与具体存储方案分开。
